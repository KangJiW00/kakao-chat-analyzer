# kakao-chat-analyzer

GitHub Pages에 배포한 뒤 애플리케이션 메뉴에 URL을 연결해 사용하는 **현장 카카오톡 대화 분석 정적 웹앱**입니다. 앱 화면에서 `.txt` 파일을 선택하거나 드래그앤드롭하고, 대화 내용을 직접 붙여넣어 즉시 분석합니다.

## 파일 구성

- `index.html`: 외부 CDN, 빌드, 서버 없이 실행되는 단일 정적 웹앱
- `README.md`: 저장소·GitHub Pages·애플리케이션 메뉴 연결 안내

## 주요 기능

- TXT 파일 선택 및 드래그앤드롭
- 대화 내용 직접 붙여넣기 및 샘플 데이터
- UTF-8 우선 디코딩, CP949/EUC-KR 대체 디코딩 시도
- 카카오톡 형식과 일반 텍스트의 날짜/시간·작성자·메시지 파싱
- 라인·공정·카테고리·작성자·상태 필터 및 검색
- 정렬, 페이지네이션, 전체 보기
- 총 건수·미조치·오늘 발생·고장/불량·저장 세션 KPI
- 고장·반복문제점·이슈사항·청소·정지·불량 자동 분류
- 상세 원문, 분류 근거, 발생시각, 작성자, 라인, 공정, 상태 확인
- 조치완료/미조치 변경 및 조치 메모 저장
- 분석 세션 localStorage 저장·복원·삭제
- JSON/CSV 내보내기
- 라인 추가·수정·삭제 및 공정/카테고리 패턴 편집
- 데이터 초기화 확인창, 반응형 UI, 키보드 포커스, 기본 ARIA 적용

## 로컬에서 확인하기

1. `index.html`과 `README.md`를 같은 폴더에 둡니다.
2. `index.html`을 최신 Chrome, Edge, Firefox에서 엽니다.
3. `샘플 데이터`를 눌러 분석 결과를 확인하거나 실제 TXT 파일을 입력합니다.
4. 실제 배포 시에도 별도 서버 없이 동일한 화면에서 사용합니다.

## GitHub 저장소에 올리기

저장소 이름을 `kakao-chat-analyzer`로 만들고 `index.html`을 저장소 **루트**에 둡니다.

### GitHub 웹 화면에서 업로드

1. GitHub 로그인 후 **New repository**를 선택합니다.
2. 저장소 이름에 `kakao-chat-analyzer`를 입력합니다.
3. 저장소를 생성합니다.
4. **Add file → Upload files**를 선택합니다.
5. `index.html`과 `README.md`를 업로드합니다.
6. 저장소 루트에 두 파일이 보이는지 확인하고 커밋합니다.

### 로컬 Git을 사용할 경우

```bash
git init
git add index.html README.md
git commit -m "Add Kakao chat analyzer static app"
git branch -M main
git remote add origin https://github.com/<사용자명>/kakao-chat-analyzer.git
git push -u origin main
```

## GitHub Pages 활성화

1. 저장소의 **Settings**로 이동합니다.
2. 왼쪽 메뉴에서 **Pages**를 선택합니다.
3. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
4. Branch는 `main`, 폴더는 `/ (root)`를 선택합니다.
5. **Save**를 누릅니다.
6. Pages 화면에 표시되는 배포 주소를 복사합니다.

일반적인 주소 형식은 다음과 같습니다.

```text
https://<사용자명>.github.io/kakao-chat-analyzer/
```

이 프로젝트는 루트의 `index.html`을 직접 제공하며 별도 라우팅을 사용하지 않습니다. 따라서 새로고침 시 별도 경로 404가 발생하지 않는 단일 페이지 구조입니다.

## 애플리케이션 메뉴에 연결해 사용하기

애플리케이션 메뉴가 외부 웹앱 URL을 등록할 수 있는 환경이라면 다음 절차로 연결합니다.

1. GitHub Pages 배포가 완료된 뒤 Pages 화면의 앱 URL을 복사합니다.
2. 사용하는 애플리케이션의 좌측 메뉴에서 **앱 추가/앱 관리/외부 앱 연결**과 같은 메뉴를 엽니다.
3. 앱 이름을 `현장 카톡 분석 앱` 또는 `카카오톡 대화 분석기`로 입력합니다.
4. URL 입력란에 복사한 GitHub Pages URL을 붙여넣습니다.
5. 저장 후 좌측 메뉴의 앱 항목을 클릭합니다.
6. 열린 앱 화면에서 TXT 업로드·드래그앤드롭·텍스트 붙여넣기 중 하나를 선택하고 `분석 실행`을 누릅니다.

채팅창에 파일을 업로드해 별도 분석 URL을 받는 방식은 사용하지 않습니다. 사용자는 애플리케이션 메뉴에서 연결된 GitHub Pages 화면 자체를 분석 도구로 사용합니다.

## 앱 내부 사용법

1. TXT 파일을 선택하거나 업로드 영역으로 끌어 놓습니다.
2. 또는 카카오톡 대화 원문을 입력창에 붙여넣습니다.
3. `분석 실행`을 클릭합니다.
4. KPI, 필터, 검색, 정렬, 페이지 이동으로 결과를 확인합니다.
5. `보기`에서 원문과 분류 근거를 확인하고 상태·조치 메모를 저장합니다.
6. `저장된 분석 이력`에서 이전 세션을 다시 열거나 삭제합니다.
7. 현재 결과는 CSV, 세션은 JSON/CSV로 내보낼 수 있습니다.

## 규칙 기반 분석

AI 분석이 아니라 편집 가능한 키워드와 정규식 규칙을 사용합니다.

- 라인: 기본 예시 `1라인`, `2라인`, `A라인`
- 공정: 조립, 검사, 가공, 포장, 용접, 도장
- 카테고리: 고장, 불량, 정지, 반복문제점, 청소, 이슈사항 순으로 우선 매칭
- 상태: `완료`, `조치`, `처리`, `교체`, `복구`, `정상화`, `해결` 등이 있으면 조치완료, 없으면 미조치
- 패턴: 설정 화면에서 쉼표로 구분해 입력합니다. 유효한 정규식은 정규식으로 처리하고, 잘못된 정규식은 문자열 포함 방식으로 대체합니다.

## localStorage 제한사항

분석 원문, 분석 결과, 설정, 분석 이력은 브라우저 `localStorage`에 저장됩니다.

- 동일한 브라우저와 동일한 기기에서만 유지됩니다.
- 다른 기기·다른 브라우저·시크릿 모드에서는 자동으로 공유되지 않습니다.
- 브라우저의 사이트 데이터/캐시를 삭제하면 저장 이력이 사라질 수 있습니다.
- 민감한 대화 내용은 공용 PC에서 사용하지 않는 것을 권장합니다.
- 백엔드나 중앙 데이터베이스가 없으므로 팀원 간 분석 이력은 공유되지 않습니다.

## 배포 상태 안내

이 작업물은 GitHub 계정 로그인, 저장소 생성, GitHub Pages 활성화, 애플리케이션 메뉴 등록을 대신 수행하지 않습니다. 사용자가 위 절차대로 파일을 업로드하고 배포 URL을 애플리케이션 메뉴에 연결해야 합니다.

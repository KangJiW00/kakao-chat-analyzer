# kakao-chat-analyzer

GitHub Pages에 배포된 URL을 애플리케이션 메뉴에 연결해 사용하는 **현장 카카오톡 대화 분석 정적 웹앱**입니다. 앱 화면에서 `.txt`를 선택하거나 드래그앤드롭하고, 대화 원문을 붙여넣어 바로 분석합니다. AI 서비스가 아니며 브라우저 내 키워드·정규식 규칙으로 분류합니다.

## 이번 수정: TXT 업로드 후 결과가 0건이던 문제

기존 문제는 파일을 읽는 흐름과 메시지 헤더 인식이 분리되어 있고, `2026. 9. 3. 오전 2:21, 이름 : 메시지`처럼 시간 뒤에 쉼표가 있는 카카오톡 형식을 기존 파서가 충분히 처리하지 못할 때 결과가 0건으로 끝날 수 있었던 점입니다.

이번 버전은 다음을 수정했습니다.

- `change`와 `drop` 이벤트를 공통 `loadFile()`로 연결
- 파일을 읽은 뒤 반드시 textarea에 원문을 표시
- 사용자가 `분석 실행`을 눌러야 분석하도록 상태 안내 표시
- UTF-8 BOM 제거 및 UTF-8 → EUC-KR/CP949 대체 디코딩
- `LF`, `CRLF`, `CR` 줄바꿈 정규화
- 오전/오후, 대괄호, 시간 뒤 쉼표, 일반 ISO 날짜 형식 파싱
- 인식된 행 수와 인식된 메시지 수 표시
- 인식 실패 시 0건으로 조용히 끝내지 않고 원인과 입력 행 수를 표시
- 날짜, 시간, 작성자, 라인, 공정, 카테고리, 고장부위, 원인, 조치, 소요시간, 내용, 조치결과를 결과 상세에 표시
- 24개 사용자 제공 라인 기준정보를 기본 설정으로 반영

## 대표 테스트 입력

다음 4개 메시지를 `대표 샘플` 버튼으로 입력해 분석할 수 있습니다.

```text
2026. 9. 3. 오전 2:21, THETMYOKHINE : KA4 30_1 공정 ATC 알람 보전 신고했습니다.
2026. 9. 3. 오전 1:10, 얀빠잉우 : 라인 : LX3 1차 / 내용 : OT / 요청 : 확인 부탁드립니다
2026. 9. 3. 오전 3:59, 얀빠잉우 : 라인 : LX3 1차 / 공정 :20-2호기 / 내용 : 탑도어 알람 / 요청 : 확인 부탁드립니다
2026. 9. 3. 오전 4:27, 명화_언양 생산B 임정원 리더 : LX3 1차 반전기 신호이상 보전호출. 10공정 휠면 팁 밀림 조치후 가동.
```

위 입력은 날짜·시간·작성자·내용을 메시지 4건으로 인식합니다. 라인 키워드와 카테고리 키워드가 매칭되며, 마지막 메시지는 `조치완료`로 분류됩니다.

## 주요 기능

- TXT 파일 선택 및 드래그앤드롭
- 대화 내용 직접 붙여넣기 및 대표 샘플
- 카카오톡 및 일반 텍스트 파싱
- 라인·공정·카테고리·작성자·상태 필터
- 검색·정렬·페이지네이션·전체 보기
- 총 건수·미조치·오늘 발생·고장/불량·세션 KPI
- 고장, 반복문제점, 이슈사항, 청소, 정지, 불량 분류
- 상세 모달에서 분류 근거, 원문, CSV형 상세 컬럼 확인
- 조치완료/미조치 변경 및 조치 메모 저장
- 분석 이력 자동 저장·복원·삭제
- 현재 결과 및 세션별 JSON/CSV 내보내기
- 라인·공정·카테고리 규칙 편집
- 데이터 초기화 확인창
- 외부 CDN·빌드·서버·백엔드 없는 단일 `index.html`

## 기본 라인 기준정보

다음 24개 라인과 패턴이 기본값으로 포함됩니다.

- LX3 1차 DISC RR: `lx[s-]?3[s-]?1차`, `lx[s-]?3[s-]?1[s-]?disc`, `lx3s*1`
- LX3 2차 DISC RR: `lx[s-]?3[s-]?2차`, `lx[s-]?3[s-]?2[s-]?disc`, `lx3s*2`
- RJ DISC RR: `rj[s.-]`, `rjs*$`
- TL NEPB DISC RR: `tl[s-]?nepb`, `tl[s-]?disc`
- MX5 DISC RR: `mx[s-]?5[s-]?disc`, `mx5`
- SX2 1차 DISC RR: `sx[s-]?2[s-]?1차`, `sx2s*1`
- SX2 3차 DISC RR: `sx[s-]?2[s-]?3차`, `sx2s*3`
- MQ4 3차 DISC RR: `mq[s-]?4[s-]?3차`, `mq4s*3s`
- SX2 2차 DISC RR: `sx[s-]?2[s-]?2차`, `sx2s*2`
- DRUM 2차 RR: `드럼[s-]?2차`, `drum[s-]?2`
- MQ4 2차 DISC RR: `mq[s-]?4[s-]?2차`, `mq[s-]?4[s-]?2s*disc`, `mq4s*2s`
- RB DISC RR: `rb[s.-]`
- MQ4 1차 DISC RR: `mq[s-]?4[s-]?1차`, `mq[s-]?4[s-]?1s*disc`, `mq4s*1s`
- SG2 DISC RR: `sg[s-]?2`
- OS CARRIER: `os[s-]?carrier`
- QX KNUCKLE: `qx[s.-]`
- DN8 KNUCKLE: `dn[s-]?8`
- MQ4 DISC FRT: `mq[s-]?4[s-]?f(?:rt)?b`, `mq[s-]?4fb`, `mq4fb`, `mq4s*f(?:rt)?b`
- MX5 1차 DISC FRT: `mx[s-]?5[s-]?1차[s-]?f`
- KA4 DISC RR: `ka[s-]?4`, `kas+4`
- LX3 FRT DISC: `lx[s-]?3[s-]?frt`
- SP3 DISC RR: `sp[s-]?3`
- NX4 CARRIER ASSY: `nx[s-]?4`
- CN7 CARRIER ASSY: `cn[s-]?7`

설정 화면에서 라인명과 패턴을 추가·수정·삭제할 수 있습니다. 패턴은 쉼표로 구분합니다.

## 지원 TXT 형식

```text
2026. 9. 3. 오전 2:21, 이름 : 메시지 내용
[2026. 9. 3. 오후 2:21] 이름 : 메시지 내용
2026-09-03 14:21 이름: 메시지 내용
2026-09-03, 오후 2:21, 이름, 메시지 내용
```

메시지 헤더 다음 줄이 헤더가 아니면 직전 메시지의 다중 줄 내용으로 이어 붙입니다. 파싱되지 않은 고립 행도 버리지 않고 결과에 포함하되 작성자는 `알 수 없음`으로 표시합니다.

## GitHub Pages 배포

1. GitHub에서 `kakao-chat-analyzer` 저장소를 생성합니다.
2. `index.html`과 `README.md`를 저장소 **루트**에 업로드합니다.
3. **Settings → Pages**로 이동합니다.
4. **Deploy from a branch**를 선택합니다.
5. Branch는 `main`, 폴더는 `/ (root)`로 지정하고 저장합니다.
6. Pages 화면에 표시된 배포 URL을 복사합니다.

일반적인 주소는 다음과 같습니다.

```text
https://<사용자명>.github.io/kakao-chat-analyzer/
```

이 앱은 저장소 루트의 단일 `index.html`을 사용하고 별도 라우팅을 사용하지 않으므로 새로고침 시 라우팅 404가 발생하지 않도록 구성되어 있습니다.

## 애플리케이션 메뉴에 연결

1. GitHub Pages 배포가 완료된 뒤 배포 URL을 복사합니다.
2. 사용하는 애플리케이션의 좌측 메뉴에서 앱 추가·외부 앱 연결 메뉴를 엽니다.
3. 앱 이름을 `현장 카톡 분석 앱`으로 입력합니다.
4. 복사한 GitHub Pages URL을 URL 입력란에 붙여넣고 저장합니다.
5. 좌측 메뉴에서 연결된 앱을 열고 TXT 업로드 또는 내용 붙여넣기를 수행합니다.
6. 앱 내부의 `분석 실행` 버튼으로 결과를 확인합니다.

채팅창에 파일을 업로드해 분석 URL을 받는 흐름은 사용하지 않습니다. 사용자는 연결된 GitHub Pages 앱 화면에서 직접 분석합니다.

## localStorage 제한사항

분석 원문, 결과, 설정, 이력은 브라우저 `localStorage`에 저장됩니다.

- 동일 브라우저·동일 기기에서만 유지됩니다.
- 다른 기기, 다른 브라우저, 시크릿 모드와 자동 공유되지 않습니다.
- 브라우저 사이트 데이터 삭제 시 이력이 사라질 수 있습니다.
- 백엔드와 중앙 데이터베이스가 없으므로 팀원 간 이력을 공유하지 않습니다.
- 민감한 대화는 공용 PC에서 사용하지 않는 것을 권장합니다.

GitHub 로그인, 저장소 생성, Pages 활성화, 애플리케이션 메뉴 연결은 실제 계정 권한이 필요하므로 사용자가 직접 수행해야 합니다.
